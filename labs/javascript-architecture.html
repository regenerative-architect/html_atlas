Start here, in plain language

What it is

As tools grow, scattered code that changes things from everywhere becomes fragile. A state machine lists every situation the tool can be in and exactly which events move it between them. Snapshots of state make undo and history simple.

Why it matters for people and planet

Predictable software is kinder software: fewer surprises, fewer lost records, easier hand-overs between volunteers. Small, well-structured code is also cheaper to maintain for groups without a full-time developer.

Try it in three steps

  1. Press the buttons to move a seed through its life: only events that make sense right now are enabled.
  2. Watch the event log and the history grow with every step.
  3. Press Undo a few times: each snapshot restores the exact earlier state.

Where people use this

  • A request form that moves through Draft, Submitted, Reviewed and Done without illegal jumps.
  • A volunteer shift tracker where every change can be undone.
  • Teaching how apps work by tracing events and states.

    More worked examples

    Three structural habits that keep a growing vanilla-JS page from turning into an unmaintainable pile of event listeners.

    A tiny finite state machine instead of scattered booleans

    Modeling "what can happen next" as an explicit transitions table catches invalid states at write time, instead of debugging why isLoading and isDone were somehow both true.

    const trafficLight={
  state:'red',
  transitions:{red:'green',green:'yellow',yellow:'red'},
  next(){this.state=this.transitions[this.state];return this.state}
};

    Expected outcome: calling trafficLight.next() three times cycles red → green → yellow → red, and there is no code path that can set an invalid fourth state.

    Decoupling components with custom events

    Two unrelated parts of a page — say a cart and a receipt panel — can communicate through the DOM itself via CustomEvent, instead of holding direct references to each other.

    function onOrderReady(callback){
  document.addEventListener('order:ready',(e)=>callback(e.detail));
}
function announceOrderReady(order){
  document.dispatchEvent(new CustomEvent('order:ready',{detail:order}));
}

    Extend it: dispatch on a specific element and let it bubble, rather than document, once more than one instance of a component exists on the page.

    Deep-cloning state with structuredClone

    JSON.parse(JSON.stringify(x)) silently drops Date, Map, and functions; structuredClone() is the built-in, spec-defined deep clone that handles most real JavaScript values correctly.

    function snapshotState(state){
  return structuredClone(state);
}

    Expected outcome: a cloned snapshot can be mutated freely without affecting the original object graph — useful for undo history or comparing before/after state.

    What this lab covers

    • A finite state machine defined as data
    • Events dispatched through a single function
    • CustomEvent and EventTarget for decoupled rendering
    • structuredClone snapshots for undo
    • Buttons enabled from the rules, not hand-written conditions
    • A readable transition table generated from the same data

    How to check it works

    1. Confirm only Water and Late frost are enabled while the state is Seed.
    2. Grow the seed to a Tree and share seeds to start a new cycle.
    3. Undo several times and confirm each step restores the earlier state exactly.
    4. Read the transition table and predict which buttons will be enabled next.
    5. Use Tab and Enter to operate everything.

    Limits and safety

    This is a teaching-sized machine. Real applications may need nested or parallel states, persistence and server synchronisation; libraries exist for that, but the core idea stays the same.

    This lab demonstrates a bounded, local example. Support varies between browsers, and anything involving permissions, devices, outside services or real security needs separate testing.

    Build it yourself with an AI assistant

    Paste this into the assistant you use, adapt it to your project, and check every result yourself. Generated code can look right and still be wrong.

    Refactor my JavaScript into a small, predictable architecture. Model the tool's states and allowed transitions as data (a finite state machine), route every change through one dispatch function that validates the event, keep state immutable and snapshot it with structuredClone so undo works, and render the UI from state (disable actions that are not allowed). Use EventTarget/CustomEvent instead of global variables for communication between parts. No framework required. Explain the state table in plain language and add tests that try every illegal transition.
